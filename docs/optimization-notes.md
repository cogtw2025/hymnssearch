# 神家詩歌搜尋：網站優化紀錄與規劃

最後更新：2026-10-08

這份文件整理 2026 年 10 月對網站所做的檢查、已完成的改進，以及接下來的規劃，供維護者參考。

---

## 一、網站現況

- **網址**：https://cogtw2025.github.io/hymnssearch/
- **架構**：純前端靜態網站，透過 GitHub Pages 發布，沒有後端伺服器，也沒有 build 步驟。
  - **push 到 `main` 約一分鐘後就會上線**，請先在本機測試再 push。
- **主要檔案**

| 檔案 | 內容 |
|---|---|
| `index.html` | 整個網站：畫面（HTML）、樣式和所有程式（內嵌在 `<script>` 裡） |
| `hymns.json` | 詩歌資料庫，約 2,400 筆，格式為 `{ code, title, collection, content }` |
| `sw.js` | Service Worker，把詩歌資料存在使用者裝置上（見下方說明） |
| `docs/` | 文件與資料核對表，不影響網站運作 |

- **外部服務**
  - 樣式：Tailwind CSS（CDN）
  - 字型：Google Fonts（Noto Sans TC）
  - 問題回報：送到 Google 表單；「觀看回報」從 Google Apps Script 讀取

### 本機測試方式

網站需要透過 HTTP 伺服器開啟（直接雙擊 `index.html` 會讀不到詩歌資料）。在專案資料夾執行：

```
python -m http.server 8765 --bind 127.0.0.1
```

再用瀏覽器開 http://127.0.0.1:8765/ 。

| 日期 | 項目 | 說明 |

### 投影模式操作方式

| 動作 | 鍵盤／簡報翻頁器 | 平板／手機 |
|---|---|---|
| 下一頁 | → ↓ 空白鍵 Enter PageDown | 點畫面右側，或往左滑 |
| 上一頁 | ← ↑ PageUp | 點畫面左側三分之一，或往右滑 |
| 黑屏（再按一次恢復） | `B` 或 `.` | — |
| 第一頁／最後一頁 | Home／End | — |
| 離開 | Esc | 移動滑鼠或點畫面後，右上角出現按鈕 |

已知限制：
- 副歌在資料中只寫一次，投影時不會在每節主歌後自動重複。
- 少數詩歌（例如 1204）歌詞後附有見證或寫作背景，也會被投影出來，需從資料面整理。
- iPhone 的 Safari 不支援網頁全螢幕，投影畫面會蓋滿網頁，但瀏覽器網址列仍會顯示。

### Service Worker 說明

Service Worker 是所有現代瀏覽器內建的功能，**免費、不需註冊任何服務、不收集使用者資料**，每台裝置約佔 2～3 MB。

| 資源 | 策略 |
|---|---|
| `hymns.json` | 先用裝置上的版本立即顯示，同時在背景下載新版；有更新時自動換上新資料 |
| 網頁與程式 | 有網路時一律抓最新版（所以 push 的修改會立即生效），沒有網路或伺服器出錯時才用裝置上的版本 |

維護時不需要做任何額外處理。iPad／iPhone 的 Safari 若 7 天沒開啟網站，可能會清掉存的資料；把網站「加入主畫面」可避免。

## 三、資料問題與核對（hymns.json）

自動檢查 `hymns.json` 後，發現以下問題，**已整理成核對表 `docs/hymns-review.xlsx`**，請熟悉詩歌本的同工對照實體詩歌本目錄填寫黃色欄位。

| 分頁 | 問題 | 數量 | 能否自動修正 |
|---|---|---|---|
| 編號重複 | 兩首不同的詩歌使用同一個編號（例：`0218` 同時是「雲間的約會」和「雲裡狂喜」） | 41 組（82 筆） | ❌ 需對照詩歌本 |
| 編號與詩歌集不符 | 第二十三集中有 5 首以 `22` 開頭，部分排序也不連貫 | 5 首 | ❌ 需對照詩歌本 |
| 合訂本編號重複 | `HH144` 出現在兩首不同詩歌 | 1 組 | ❌ 需對照詩歌本 |
| 特殊字元 | 字型專用字元，在 iPad／手機上顯示成空白或方框 | 22 處 | ❌ 需對照詩歌本 |
| 部首字修正 | 外觀與一般字相同、實為部首符號的字（例：「⼭」不是「山」），造成**搜尋不到** | 22 首、390 處 | ✅ 有標準對照，確認後可自動修正 |
| 詩歌集標題列 | 沒有歌詞、當作詩歌集標題的資料，編號與寫法不一致 | 26 筆 | 需決定保留或刪除 |
| 缺號清單 | 各詩歌集編號範圍內缺少的編號 | 23 個詩歌集 | 需判斷是本來就未收錄，還是編號錯誤 |

另外，「全部詩歌」分頁列出所有資料，可依「問題標記」篩選，其他發現的錯誤也可直接填寫在此頁。

**處理流程**

1. 同工填寫 `docs/hymns-review.xlsx` 的黃色欄位
2. 交回後，由程式將修正套用回 `hymns.json`，並再次檢查有無重複編號或格式錯誤
3. 確認無誤後 push 上線

**提醒**：之後規劃的「每首詩歌有自己的網址」會以編號作為網址，**建議先完成編號修正**，以免已分享的連結日後失效。

## 四、接下來的規劃

### 建議優先處理

| 項目 | 效果 | 工作量 |
|---|---|---|
| **修正詩歌資料** | 依核對表修正編號與文字；部首字可先自動修正，讓搜尋更準確 | 依核對進度 |
| **每首詩歌有自己的網址** | 例：`#/hymn/0015`。可把詩歌連結傳到 LINE，對方點開直接看到該首；返回手勢可回到列表，不會離開網站；重新整理仍停在同一首。**不會開新分頁或重新載入**，速度與現在相同 | 中 |
| **聚會歌單** | 排好當天要唱的詩歌，投影時連續往下翻；歌單可用連結分享給同工 | 中 |
| **改用系統內建字型** | 不必下載 Google 字型，網站更快；iPad 使用蘋方體，字更清楚。各平台字體會略有不同 | 小 |
| **投影時自動重複副歌** | 每節主歌後自動插入副歌，可開關 | 小 |
| **我的最愛改用編號辨識** | 目前以歌名辨識，有 46 個歌名重複會互相影響；也是日後跨裝置同步的前置工作 | 小 |

### 需要先討論的項目

**我的最愛跨裝置同步**

目前「我的最愛」只存在使用者自己的瀏覽器中，換裝置或清除瀏覽資料就會消失。可行方案：

| 方案 | 做法 | 優點 | 缺點 |
|---|---|---|---|
| A. 同步連結 | 產生帶有收藏清單的網址或 QR Code，在其他裝置開啟即可匯入 | 簡單、免費、無個資問題 | 不是自動同步，每次修改都要重新傳 |
| **B. Google 登入 + Firebase（建議）** | 使用者以 Google 帳號登入，收藏存在雲端並自動同步；未登入時維持現狀 | 真正自動同步，用量在免費額度內 | 需以**教會公用的 Google 帳號**建立 Firebase 專案；會存使用者 email，需加隱私說明 |
| C. 同步碼 + Google 試算表 | 沿用現有的 Apps Script，以同步碼對應清單 | 不必申請新服務 | 同步碼外流即可被修改、速度慢、有使用次數上限，不建議 |

**加入主畫面的圖示**

已設計 5 款圖示草稿（黑底「詩」、「神家詩歌」方印、紅色印章、詩歌本與音符、白底明體「詩」），目前暫不採用。加入後，網站加到主畫面時會有專屬圖示、全螢幕開啟、不受 Safari 7 天清除資料的限制。

**Tailwind CSS 改為預先產生的檔案**

目前使用的 Tailwind CDN 官方不建議用於正式網站，會在使用者瀏覽器中即時產生樣式。可改用 GitHub Actions 在 push 時自動產生 CSS，維護方式不變。

## 五、技術方向的決定

**維持原生 JavaScript，暫不改用 Vue 等框架。**

- 實際運作的程式約 750 行，功能單純（搜尋、列表、顯示），框架帶來的好處有限。
- 改用框架需要安裝 Node.js、執行 build、設定部署流程，會提高維護門檻；目前維護方式是直接修改 HTML 後 push 即上線。
- 上述各項改進（安全修補、網址、離線、歌單）以原生寫法都能完成。
- 若日後需要登入帳號、線上編輯詩歌、多人即時同步歌單等較複雜的功能，再評估 Vue 或 Svelte。

## 六、測試網址

GitHub Pages 一個 repo 只能發布一個 branch，因此無法以 branch 建立測試網址；`raw.githack.com`、jsDelivr 等第三方服務也因資料檔過大或網頁格式問題無法使用。

需要在 iPad 等裝置上測試新功能時，可將 repo **fork 到個人帳號**並開啟 GitHub Pages，取得獨立的 https 測試網址，確認後再 push 到正式站。注意：測試站的「問題回報」仍會送到正式的 Google 表單，測試時請勿送出。
